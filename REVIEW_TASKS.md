# Предложенные задачи по улучшению кодовой базы

## 1) Исправление опечатки
**Где:** `android/app/src/main/res/values/strings.xml`

**Проблема:** имя приложения в ресурсе задано как `application` (строчными буквами). Для пользовательского названия это выглядит как опечатка/черновой плейсхолдер.

**Задача:** заменить значение `app_name` с `application` на нормализованное название продукта (например, `Habit Tracker`).

---

## 2) Исправление ошибки
**Где:** `android/app/src/main/java/com/example/application/Home.kt`

**Проблема:** `viewModel.loadData()` вызывается дважды через два `LaunchedEffect(Unit)`, что приводит к дублирующим сетевым вызовам и лишней перезагрузке состояния.

**Задача:** оставить только один `LaunchedEffect(Unit)` с вызовом `viewModel.loadData()`.

---

## 3) Исправление комментария/документации
**Где:** `backend/README_DEV.md`

**Проблема:** в шаге про миграции написано, что команда добавляет только таблицы привычек (`habits`, `habit_weekdays`, `habit_targets`), но в проекте уже есть миграции пользователей, логов и изменения типа `color_argb`.

**Задача:** обновить описание шага миграций так, чтобы оно соответствовало текущему состоянию схемы БД (users, habits, habit_weekdays, habit_targets, habit_logs и последующие изменения).

---

## 4) Улучшение теста
**Где:** `backend/tests/test_habit_schedule_helper.py`

**Проблема:** в модуле есть `autouse`-фикстура `clean_db`, которая ничего не делает и не нужна для unit-тестов чистых helper-функций.

**Задача:** удалить фикстуру и добавить тест на невалидные значения `weekday` (например, `"7"`, `"SOMEDAY"`), чтобы явно зафиксировать ожидаемое поведение `is_habit_scheduled_for_date` при некорректных данных.
